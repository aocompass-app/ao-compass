## 2026-08-02 ／ 担当分野: 志望校（AO_HOUR=15 → 15 % 7 = 1）

### 入れた改善

**1. 志望校カードに「次にやってくる日」を出すようにした**

- `nextMilestone(s)` を新設（`countdownBox` の直前）。
  エントリー開始 → 出願締切 → 試験日 → 合格発表 のうち、
  今日以降でいちばん近い日を返す。すべて過去なら `null`。
- `schoolCard(s)` のバッジを `s.deadline` 固定から `nextMilestone(s)` 由来に変更。
  いちばん近い日が出願締切でないときは、出願締切の日付を小さい字で下に残す。
- 合格発表だけは赤（alert）にしない。急かす場面ではないため。
- `dateWithIn(iso)` を新設し、詳細シートの
  エントリー開始／出願締切／試験日／合格発表の4行すべてに残り日数を付けた。

なぜ: 出願締切を過ぎた瞬間にカードが灰色の「締切済」になり、
まだ先にある試験日・合格発表が画面から消えていた。
9〜11月は「出願は終わったが試験はこれから」の生徒が多く、この時期にカードが死んでいた。

**2. 志望校の詳細シートに「この大学に出す書類」の進み具合を追加**

- `openSchool(id)` の項目一覧と出願チェックリストの間に挿入。
- `requiredDocs(s)` / `docProgress(s,label)` / `newDocFor(s,label)` は既にあったのに
  このシートからは使われておらず、`s.docs` の生テキストが並ぶだけだった。
- 書類ごとに 完成 / 書き途中 / 未着手 と文字数を出し、
  「開く」（既存の書類 → `openDocEditor`）「作る」（`newDocFor`）ボタンを付けた。
- 見出しの右に「1/3 完成」の集計バッジ。

なぜ: 志望校を見ている流れのまま、その大学に出す書類に手を付けられるようにするため。
今までは志望校 → 書類画面 → 目的の書類を探す、という遠回りが必要だった。

**3. （ついで）オブジェクトスプレッドを1か所だけ除去**

- 2665行目 `const c={...d, ...}`（書類の複製）を `Object.assign` に書き換え。
- 今回の変更とは無関係だが、リポジトリの決まり（古い iOS Safari 対応のため
  オブジェクトスプレッドを使わない）に反しており、構文チェックが赤になるため直した。
  意味は完全に同じ。

`APP_VER` は `2026.08.11` → `2026.08.02`（当日）に更新。
※ 元の値が当日より先の日付になっていたため、見かけ上は数字が戻る。
   比較は `!==` だけなので動作に影響はない。

### 見送った案

- **進捗リング `schoolProgress` を書類の実状（`docProgress`）と連動させる**
  → 手動チェックとの二重管理になり、生徒が自分でチェックを外せなくなる。
     既存 `checklist` データの意味も変わるため見送り。
- **志望校の検索を `kata2hira` でひらがな対応にする**
  → `SCHOOL_DB` の読みは登録済みの志望校オブジェクトに保存されておらず、
     登録名からは読みを引けない。効果が薄いので見送り。
- **出願チェックリストの10項目を `requiredDocs(s)` から動的生成する**
  → `schoolProgress` が固定キー10個を前提にしており、
     既にチェック済みのデータが失われる。危険なので見送り。

### 次回への申し送り

- `.list-row` の位置ずれを測るときは、**文字の読み込みで全体が 1.4px ほど落ち着く**ため、
  基準を取る前に 700ms ほど待つこと。待たないとクリックのせいだと誤解する。
- 390x844 では下の方の行が画面外に出る。押す前に `scrollIntoViewIfNeeded()` すること。
- `view` と `APP_VER` は `let` / `const` なので `window.view` では読めない。
  `page.evaluate(() => view)` のように素の名前で読む。
